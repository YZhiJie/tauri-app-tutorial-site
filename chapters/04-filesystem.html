第 4 章 · 文件系统交互 ​

小塔：「内存里的数据一关就没。本章我们给笔记找一个安全的『家』，还要防止两个进程打架。」

本章学习目标 ​

  • 掌握 Tauri 的标准数据目录与三平台映射
  • 理解两种文件操作路线（前端插件 vs Rust 命令）的分工
  • 实现原子写入与基于内容指纹的冲突检测
  • 学会 tauri-plugin-fs 的安装、授权（scope）与常用 API
  • 建立路径安全意识，防路径穿越注入

4.1 数据应该存在哪里 ​

不要自己拼 ~/xxx：路径分隔符、目录约定每个平台都不同。Tauri 提供了一系列标准目录解析，业务数据首选 app_data_dir()：

平台app_data_dir 实际位置（identifier 为 com.aninotes.app）
WindowsC:\Users\<用户>\AppData\Roaming\com.aninotes.app
macOS~/Library/Application Support/com.aninotes.app
Linux~/.local/share/com.aninotes.app（遵循 XDG）

其他常用目录还有 app_config_dir、app_cache_dir、app_log_dir、document_dir 等（通过 app.path() 获取）。

🦀 钳钳的悄悄话

为什么目录和 identifier 绑定？因为同一台机器上可能装多个 Tauri 应用， identifier 是它们互不干扰的命名空间。这也解释了第 1 章为什么强调 identifier 要填反向域名。

4.2 两条文件操作路线 ​

路线一：tauri-plugin-fs（前端直接操作）路线二：Rust 命令 + std::fs（本应用采用）
代码位置前端 TSRust
权限模型capability 授权 + 路径 scope 白名单Rust 全权，安全边界靠自己代码约束
适合场景用户「指定文件」的读写、简单导入导出、日志查看业务数据的内部持久化、需要原子性/冲突处理/复杂校验
灵活性受 scope 限制完全自由

本应用的分工：笔记持久化走 Rust（需要原子写和冲突检测）； tauri-plugin-fs 用于后续的「导入/导出」功能（第 5 章配合 dialog 实现）。

4.3 磁盘布局与启动加载 ​

每条笔记一个文件，天然「一损不俱损」：

<app_data_dir>/
└── notes/
    ├── n-192837abcd.json
    ├── n-192839ef01.json
    └── ...

启动流程（main.rs 的 setup 中）：

rust
let storage = NotesStorage::open(app.handle())?;       // 创建/打开目录
let mut notes = storage.load_all().unwrap_or_default(); // 读取全部 json
if notes.is_empty() {
    notes = default_seeds();                            // 首次启动写种子
    for note in &notes { storage.write(note)?; }
}
// 登记指纹后注入内存状态

4.4 原子写入：tmp + rename ​

直接 fs::write 有个隐患：进程写到一半崩溃 / 断电，原文件就被截断损坏了。标准做法：

rust
fn write(&self, note: &Note) -> Result<u64, String> {
    let path = self.note_path(&note.id);
    let tmp = self.dir.join(format!("{}.tmp", note.id));

    fs::write(&tmp, bytes)?;        // ① 全部写入临时文件
    fs::rename(&tmp, &path)?;      // ② 同分区 rename 是原子操作
    Ok(fingerprint(&bytes))
}

外部观察者只能看到「旧文件」或「新文件」，永远看不到半成品。

4.5 冲突检测：内容指纹 + 乐观锁 ​

真实世界里会发生：用户开着两个应用实例、或者直接用编辑器改了 JSON。 如果不管不顾地写，外部修改会被静默覆盖。

机制很简单，记住三张「账」：

  1. 每次成功写入后，记录内容指纹（64 位 hash）；
  2. 下次写入前，重新读取磁盘文件算指纹；
  3. 两个指纹对不上 → 说明文件在应用外被改过 → 拒绝写入并返回错误。
rust
fn persist_update(&self, note: &Note) -> Result<(), String> {
    // ...
    if let Some(disk_now) = s.current_fingerprint(&note.id) {
        if let Some(mem_hash) = hashes.get(&note.id) {
            if *mem_hash != disk_now {
                return Err("笔记在应用外被修改，已中止保存（请先重新加载）".into());
            }
        }
    }
    let new_hash = s.write(note)?;
    hashes.insert(note.id.clone(), new_hash);
    Ok(())
}

前端收到这个 Err，会通过顶部提示条告知用户（见 useNotes 的 notifyError）。

⚠️ 注意 hash 的定位

这里用的是标准库哈希，只做「变化检测」，防的是意外覆盖。 如果要防恶意篡改（比如更新包），必须用加密签名——那正是第 8 章 updater 做的事。

写操作的顺序原则 ​

本章所有写方法都遵循：先落盘成功，再改内存。磁盘失败时内存完全不受影响，无需回滚逻辑。 （删除也一样：先删文件再移除内存项。）

4.6 tauri-plugin-fs 完整上手 ​

① 安装 ​

bash
# Rust 侧
cd src-tauri
cargo add tauri-plugin-fs@2

# 前端侧
cd ../
pnpm add @tauri-apps/plugin-fs

② 注册插件 ​

rust
fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init()) // ← 注册
        // ...
        .run(tauri::generate_context!())
        .expect("error");
}

③ 授权：权限 + scope ​

文件插件默认任何路径都不能访问。在 capabilities/default.json 中加权限并划定 scope：

json
{
  "permissions": [
    "core:default",
    "fs:default",
    "fs:allow-read-text-file",
    "fs:allow-write-text-file",
    {
      "identifier": "fs:scope",
      "allow": ["$APPDATA/**", "$DOCUMENT/**"]
    }
  ]
}
  • $APPDATA、$DOCUMENT、$DOWNLOAD、$HOME 等是 Tauri 提供的路径变量；
  • scope 是 glob 白名单，超出白名单即使开了 allow 权限也会被拒；
  • 最小化原则：只给业务真正需要的目录。

④ 前端读写示例 ​

ts
import { readTextFile, writeTextFile, exists } from "@tauri-apps/plugin-fs";

const path = "notes/welcome.txt"; // 相对路径基于 scope 解析

if (await exists(path)) {
  const text = await readTextFile(path);
  console.log(text);
}

await writeTextFile(path, "你好，文件系统！", {
  baseDir: BaseDirectory.AppData, // 显式指定基准目录更清晰
});

二进制文件用 readFile / writeFile（Uint8Array）；还有 mkdir、remove、rename、 readDir 等 API，命名与 std::fs 基本对应。

🦀 练习预告

第 5 章装好 dialog 后，「用户选一个 .txt 文件导入成笔记」只需十几行代码： dialog.open 拿到路径 → readTextFile 读出内容 → invoke create_note。

4.7 路径安全：防穿越注入 ​

文件路径一旦混入业务 ID，就必须假设 ID 是「攻击者可控」的。本章的防御：

rust
let safe: String = id
    .chars()
    .filter(|c| c.is_ascii_alphanumeric() || *c == '-')
    .collect();
self.dir.join(format!("{safe}.json"))

../evil 会被剥成 evil；a/b 会被剥成 ab，永远跳不出 notes/ 目录。 永远不要直接 format!("{dir}/{id}.json")——这是典型的路径穿越漏洞。

课后练习：

  1. 找到你系统上的 AniNotes 数据目录，用编辑器手动修改一条笔记并保存，再回应用里编辑同一条——观察冲突提示。
