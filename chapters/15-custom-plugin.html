第 15 章 · 自研 Tauri 插件：把能力打包成可复用单元 ​

钳钳：「我们一直在用官方插件，本章拆开看看里面的构造——看完你会发现，插件并没有什么魔法，就是一套约定。」

本章学习目标 ​

  • 说清 Tauri 插件的本质：命令 + 权限 + 初始化逻辑的自包含打包
  • 从零搭出一个本地插件 crate（note-stats：文本统计）
  • 理解插件命令的寻址格式 plugin:<插件名>|<命令名>
  • 掌握插件权限的生成与授权链路（build.rs 自动生成 → default.toml → capabilities）

15.1 什么时候该写自己的插件 ​

先泼一盆冷水：大多数「业务命令」不该做成插件。判断标准：

情况选择
逻辑和本应用的业务数据/状态强相关普通模块（notes/commands.rs 那套）
逻辑通用、无业务依赖，可能搬到别的项目复用插件
需要自己的权限体系（细粒度授权某些命令）插件
想发布到社区给别人用插件（独立仓库 + crates.io）

本章选「文本统计」做教学例子正因为它零业务依赖：给它一段文本，还你字符/词/行数。放在任何 Tauri 项目里都能用。

🦀 钳钳的悄悄话

插件与普通模块的运行时成本完全一样——都是编译进同一个二进制的 Rust 代码。插件的价值在工程组织（复用、权限、版本化），不在性能。

15.2 插件 crate 的标准结构 ​

在 src-tauri/plugins/note-stats/ 下新建一个 crate，四个文件各司其职：

plugins/note-stats/
├── Cargo.toml          # 清单：links 字段是关键
├── build.rs            # 声明命令列表，自动生成权限文件
├── permissions/
│   └── default.toml    # 默认权限集（手写，引用自动生成的条目）
└── src/
    └── lib.rs          # 命令实现 + init() 插件入口

Cargo.toml：

toml
[package]
name = "note-stats"
version = "0.1.0"
edition = "2021"
rust-version = "1.77.2"
# links 是 Tauri 插件的硬性约定：主应用的 tauri-build 靠它定位插件的
# permissions 目录，把权限并入应用的 ACL 清单；缺失会报 LinksMissing
links = "note-stats"

[build-dependencies]
tauri-plugin = { version = "2", features = ["build"] }

[dependencies]
tauri = "2"
serde = { version = "1", features = ["derive"] }

build.rs——命令清单驱动权限生成：

rust
//! 插件的每个命令都要登记进 COMMANDS：
//! tauri_plugin 会据此在 permissions/autogenerated/commands/ 下
//! 生成 allow-<命令> / deny-<命令> 权限文件（不提交手写），
//! 再由 permissions/default.toml 组合成默认权限集。
const COMMANDS: &[&str] = &["stats"];

fn main() {
    tauri_plugin::Builder::new(COMMANDS).build();
}

构建时它会在 permissions/autogenerated/commands/ 下生成 stats.toml，内容为 allow-stats / deny-stats 两个权限条目——这些文件是生成的，别手写。

permissions/default.toml——把自动生成的条目组合成默认权限集：

toml
"$schema" = "schemas/schema.json"

[default]
description = "允许调用 note-stats 插件的 stats 命令"
permissions = ["allow-stats"]

src/lib.rs——命令实现与插件入口：

rust
use tauri::{
    plugin::{Builder as PluginBuilder, TauriPlugin},
    Runtime,
};

/// 统计结果（rename_all 让前端拿到 camelCase 字段）
#[derive(Debug, Clone, serde::Serialize)]
#[serde(rename_all = "camelCase")]
pub struct Stats {
    pub chars: usize,  // 字符数（不含空白字符）
    pub words: usize,  // 词数：英文按空白分词，中文逐字计词
    pub lines: usize,  // 行数
}

/// stats 命令：统计一段文本的字符 / 词 / 行数
#[tauri::command]
fn stats(text: String) -> Stats {
    let lines = text.lines().count();
    let mut chars = 0usize;
    let mut words = 0usize;
    let mut in_word = false;

    for c in text.chars() {
        if c.is_whitespace() {
            in_word = false;
            continue;
        }
        chars += 1;
        if !c.is_alphanumeric() {
            in_word = false;          // 标点：分隔符，不计词
        } else if c.is_alphabetic() && !c.is_ascii() {
            words += 1;               // 全角字母（中/日/韩）：逐字成词
            in_word = false;
        } else if !in_word {
            words += 1;               // ASCII 字母数字：连续一段算一个词
            in_word = true;
        }
    }
    Stats { chars, words, lines }
}

/// 插件入口：主应用通过 `.plugin(note_stats::init())` 注册。
/// 插件名 "note-stats" 决定了前端寻址前缀与权限名空间（note-stats:xxx）。
pub fn init<R: Runtime>() -> TauriPlugin<R> {
    PluginBuilder::new("note-stats")
        .invoke_handler(tauri::generate_handler![stats])
        .build()
}

15.3 接入主应用：三步 ​

第一步，主 crate 的 Cargo.toml 加 path 依赖，并把插件纳入 workspace（共享 target 缓存与锁文件）：

toml
[workspace]
members = ["plugins/note-stats"]

[dependencies]
note-stats = { path = "plugins/note-stats" }

第二步，main.rs 注册插件（和官方插件一模一样的姿势）：

rust
.plugin(note_stats::init())

第三步，capabilities/default.json 授权（否则前端调用会被 ACL 拒绝）：

json
"permissions": [
  "core:default",
  "dialog:default",
  "...": "...",
  "note-stats:default"
]

15.4 前端调用：寻址格式是关键 ​

插件命令不在顶层命名空间，寻址格式是 plugin:<插件名>|<命令名>。新建 lib/stats.ts 封装：

ts
import { invoke, isTauri } from "@tauri-apps/api/core";

/** 与 Rust 端 Stats 结构一一对应（serde rename_all = "camelCase"） */
export interface Stats {
  chars: number;
  words: number;
  lines: number;
}

/** 统计文本的字符 / 词 / 行数 */
export async function noteStats(text: string): Promise<Stats> {
  if (!isTauri()) {
    return mockStats(text); // 浏览器 mock：同规则的 TS 简化实现
  }
  return invoke<Stats>("plugin:note-stats|stats", { text });
}

NoteEditor.vue 的状态栏从「本地数字数」升级为「插件统计」，因为调用是异步 IPC，加 300ms 防抖：

ts
const stats = ref<Stats>({ chars: 0, words: 0, lines: 0 });
let statsTimer: ReturnType<typeof setTimeout> | null = null;

watch(
  () => props.note?.content ?? "",
  (text) => {
    if (statsTimer) clearTimeout(statsTimer);
    statsTimer = setTimeout(async () => {
      stats.value = await noteStats(text);
    }, 300);
  },
  { immediate: true },
);

模板里一行展示三项指标：

html
<span>字符 {{ stats.chars }} · 词 {{ stats.words }} · 行 {{ stats.lines }}</span>

15.5 插件机制的完整链路（一张图看懂） ​

build.rs COMMANDS=["stats"]
        │  tauri_plugin::build（编译期）
        ▼
permissions/autogenerated/commands/stats.toml   （allow-stats / deny-stats）
        │  被 default.toml 组合
        ▼
permissions/default.toml                        （note-stats:default）
        │  tauri-build 经 links="note-stats" 定位
        ▼
capabilities/default.json 授权                  （"note-stats:default"）
        │
        ▼
前端 invoke("plugin:note-stats|stats")  ──ACL 校验──>  Rust stats() 执行

理解这条链路后，官方插件对你再无秘密：它们只是多了 JS API 包（@tauri-apps/plugin-xxx，本质也是帮你写好 invoke 调用）和更复杂的命令集。

15.6 常见报错速查 ​

现象原因解决
编译报 LinksMissing / 权限找不到插件 Cargo.toml 没写 links加 links = "note-stats"（与插件名一致）
Permission note-stats:default not found同上，或 default.toml 文件名/位置不对检查 permissions/default.toml 路径
前端调用报「不允许执行」capabilities 没授权加 "note-stats:default"
plugin names cannot contain underscorescrate 名含下划线插件名统一用连字符（note-stats）
改了命令但权限没更新build.rs 的 COMMANDS 没同步加每个 #[tauri::command] 都要登记进 COMMANDS
找不到命令 `plugin:note-statsstats`寻址格式写错（少了 plugin: 前缀）

15.7 小结与课后练习 ​

本章你已完成：note-stats 本地插件 crate（Cargo.toml + build.rs + permissions + lib.rs 四件套）；workspace 纳入与 path 依赖；capabilities 授权；前端 plugin:note-stats|stats 寻址调用；编辑器状态栏三项统计。应用升级到 v0.14.0。

课后练习：

  1. 给插件加第二个命令 reading_time(text)（按 300 字/分钟估算阅读时长），走完整链路：COMMANDS 登记 → default.toml 加权限 → 前端调用。（体会「加一个命令要动哪几处」）
  2. 把插件改成带状态：插件内部 manage 一个计数器，记录 stats 被调用的总次数，加命令 call_count() 返回它。（提示：PluginBuilder::setup(|app, api| { ... })）
  3. 进阶阅读：打开任一官方插件的源码（如 tauri-plugin-dialog），对照本章的四件套结构，找到它的 COMMANDS、permissions 与 init()，验证「插件没有魔法」。
