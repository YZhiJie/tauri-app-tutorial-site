第 2 章 · 界面设计与 Rust 命令调用 ​

小塔：「先搭出看得见的界面，再让它学会和 Rust 核心说话——本章我们完成这两件事。」

本章学习目标 ​

  • 搭建 AniNotes 的完整界面骨架（顶部栏 + 侧边栏 + 编辑器）
  • 理解 Vue 组件的拆分原则与父子通信
  • 写出第一个 #[tauri::command] 并在前端用 invoke 调用
  • 掌握命令调用的类型安全封装与错误处理

2.1 界面布局设计 ​

桌面笔记应用的经典三区布局，也是本章的目标效果：

┌──────────────────────────────────────────────┐
│  🦀 IPC 试验场   [名字输入框]      [打招呼]   │  ← GreetPanel
├────────────┬─────────────────────────────────┤
│ 📒 我的笔记 │  笔记标题（大输入框）            │
│  ▸ 笔记 A   │  ─────────────────────         │
│    笔记 B   │                                 │
│    笔记 C   │  正文编辑区（多行文本）           │  ← NoteEditor
│            │                                 │
│            │                              字数│
└────────────┴─────────────────────────────────┘
        ↑ NoteSidebar

组件拆分原则：界面按「区域职责」拆成三个组件，数据统一放在 App.vue，子组件通过 props 接收、通过 emit 上抛事件。这是 Vue 最基础也最重要的单向数据流模式。

组件职责通信方式
GreetPanel.vue调用 greet 命令并展示回复直接调用 lib/core.ts
NoteSidebar.vue展示笔记列表、新建/选中props: notes/activeId；emit: select/create
NoteEditor.vue编辑标题与正文props: note；emit: update

2.2 共享数据结构 ​

前后端交流的第一步是定义「共同语言」。src/types.ts 中定义笔记类型：

ts
export interface Note {
  id: string;
  title: string;
  content: string;
  updatedAt: string; // ISO 8601
}

🦀 钳钳的悄悄话

养成先定义类型、再写功能的习惯。第 3 章起 Rust 命令会直接接收/返回这个结构， TS 接口就是 Rust struct 的「设计图纸」。

2.3 第一个 Rust 命令 ​

在 src-tauri/src/commands/greet.rs 中写下：

rust
/// 接收一个名字，返回问候语。
#[tauri::command]
pub fn greet(name: &str) -> String {
    format!("你好，{name}！我是 Rust 核心，消息已收到 🦀")
}

逐行理解：

  • #[tauri::command]：属性宏。它会自动生成命令注册所需的元信息，包括参数解析与返回值序列化。没有它，函数只是一个普通 Rust 函数。
  • name: &str：命令参数。Tauri 通过 serde 把前端传来的 JS 值反序列化成 Rust 类型；&str 这种引用参数由框架自动管理生命周期，是 Tauri 支持的便捷写法。
  • -> String：返回值。任何实现 serde::Serialize 的类型都能返回给前端，包括结构体、枚举、Result<T, E>。

命令必须注册才能被调用 ​

光有函数还不够，main.rs 中要把它放进 invoke_handler 路由表：

rust
mod commands;
use commands::greet::greet;

fn main() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![greet]) // ← 注册
        .run(tauri::generate_context!())
        .expect("启动 AniNotes 时发生错误");
}

generate_handler![greet] 会把函数名 greet 映射为命令名。前端调用不存在的名字时，会收到类似：

text
Command greet not found. Did you forget to register it?

—— 这是新手排名第一的报错，原因永远是「写了命令但没注册」或「名字拼错」。

2.4 前端调用：invoke 与封装层 ​

最直白的调用方式是：

ts
import { invoke } from "@tauri-apps/api/core";

const msg = await invoke<string>("greet", { name: "小塔" });

注意第二个参数 { name: "小塔" }：key 必须和 Rust 参数名逐字符一致，大小写敏感。写错 key，Rust 端会报反序列化错误（缺少字段 name）。

本教程要求把所有命令收敛到 src/lib/core.ts 一个出口，并解决一个实际问题——界面在普通浏览器里也要能调试：

ts
import { invoke, isTauri } from "@tauri-apps/api/core";

export async function greet(name: string): Promise<string> {
  if (!isTauri()) {
    return `你好，${name}！（浏览器 mock：装上 Tauri 后会收到 Rust 回复）`;
  }
  return invoke<string>("greet", { name });
}
  • isTauri() 是 Tauri v2 提供的环境检测函数（原理是检查注入的 IPC 全局对象）；
  • 浏览器中走 mock 分支，pnpm dev 即可调样式，不必每次都编译 Rust；
  • 组件只依赖 greet() 这个干净的函数签名，完全不关心底层是 IPC 还是 mock。

GreetPanel.vue 中的调用与错误处理：

ts
async function sayHello() {
  loading.value = true;
  try {
    reply.value = await greet(name.value.trim() || "旅人");
  } catch (err) {
    // Rust 返回 Err、命令不存在、参数解析失败都会进这里
    reply.value = `调用失败：${String(err)}`;
  } finally {
    loading.value = false;
  }
}
</script>

2.5 命令如何返回错误 ​

实际开发中命令不可能总成功（文件不存在、校验失败……）。Rust 惯例是返回 Result， Tauri 命令也支持：Ok(T) 会被 resolve，Err(E) 会被 reject 到前端 catch。

先记住这个模式，下一章我们就会大量使用：

rust
#[tauri::command]
fn may_fail(input: u32) -> Result<String, String> {
    if input > 10 {
        Ok("合法输入".into())
    } else {
        Err("输入必须大于 10".into()) // 前端 catch 能拿到这句中文错误
    }
}

生产级项目推荐用 thiserror 定义错误枚举而不是 String，第 4、10 章会演示。

2.7 常见报错速查 ​

现象原因解决
Command xxx not found命令没在 generate_handler! 注册注册并确认名字拼写
invalid args: missing field xinvoke 第二参数的 key 与 Rust 参数名不一致对照参数名（注意驼峰/下划线）
error: expected ... found ...（编译期）命令参数/返回值没实现 serde 反序列化/序列化给 struct 加 #[derive(serde::Deserialize)] 等
点按钮没反应没 await / 没 catch，错误被静默在 catch 中打印错误
浏览器中 invoke 报错浏览器环境没有 IPC使用 isTauri() 分支（本章做法）

⚠️ 参数命名细节

Tauri v2 默认要求 JS 侧使用 camelCase、Rust 侧使用 snake_case 时需留意： 简单参数（name）不受影响；多词参数（如 note_id）推荐 Rust 端也写成一个词， 或用 serde 属性指定，避免来回踩坑。第 4 章有实例。

2.8 小结与课后练习 ​

本章你已完成：三区笔记界面、组件化拆分、第一个 Rust 命令与类型安全的前端封装。

课后练习：

  1. 给 greet 增加第二个参数（如 greet(name, mood)），完成前后端联调。你需要改几个地方？
  2. 把命令改成返回 Result<String, String>：当名字为空字符串时返回 Err，观察前端 catch 的表现。
