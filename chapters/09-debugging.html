第 9 章 · 调试技巧与常见问题 ​

钳钳：「Bug 不可怕，可怕的是没有证据。调试 = 提出假设 → 插桩收集证据 → 缩小范围。」

本章学习目标 ​

  • 建立分层日志体系，知道每种日志去哪看
  • 熟练打开三平台 WebView 开发者工具
  • 掌握「白屏 / 命令失败 / 权限拒绝 / 资源不显示」四大高频问题诊断法
  • 学会定位主线程阻塞与跨平台疑难杂症

9.1 日志体系：先分清四种日志 ​

日志来源查看位置
前端日志console.*WebView devtools Console
Rust 标准输出println! / eprintln!启动 tauri dev 的终端
Rust 结构化日志log crate（info!/error!）终端（配 env_logger）或落盘（配 tauri-plugin-log）
崩溃日志panic / 系统崩溃报告终端 panic 栈；系统崩溃报告器

推荐：tauri-plugin-log ​

教学阶段 println! 够用；应用一旦分发，用户不会给你看终端——此时应把日志写入文件：

rust
// Cargo.toml: tauri-plugin-log = "2"
.plugin(
    tauri_plugin_log::Builder::new()
        .level(log::LevelFilter::Info)
        .build(),
)

前端通过 @tauri-apps/plugin-log 的 trace/info/error 写入同一处。 日志文件位于平台日志目录（macOS ~/Library/Logs/<identifier> 等）， 「关于」弹窗里可以加个按钮打开它——排障时请用户导出日志是最常见的支持手段。

⚠️ 日志禁忌

不要打印密码、完整令牌、用户隐私。日志文件不是秘密保险箱。

9.2 打开 WebView 开发者工具 ​

三平台在 debug 构建 下的方式：

平台打开方式
Windows / Linux窗口内右键 → 检查（Inspect）；或 F12
macOS右键 → 检查；快捷键 ⌘⌥I

要点：

  • release 构建默认没有 devtools（体积与安全考虑）；
  • 需要在 release 排障时，临时给 tauri 加 devtools feature： tauri = { version = "2", features = ["devtools"] }，排完务必去掉；
  • Console 的报错会明确标出 CSP 拦截（Refused to load ...）、资源 404、未捕获 Promise。

9.3 tauri dev 启动失败排查 ​

按启动链路逐段定位，不要盯着最终报错：

text
① 前端 dev server 是否起来？  → 浏览器直接打开 http://localhost:1420
② 端口是否被占用？           → lsof -i :1420（换端口或杀进程）
③ Rust 是否编译失败？         → 看终端中 cargo 输出的 error[E...]，不是最后的 ELIFECYCLE
④ 窗口白屏？                 → 9.4

命令行环境坑：

  • Windows 控制台中文乱码：chcp 65001 切 UTF-8；
  • 构建脚本被包管理器拦截（pnpm 的 onlyBuiltDependencies）： 在 pnpm-workspace.yaml 声明，或直接调用 node_modules/.bin/ 下的二进制；
  • Node/Rust 版本不符：回到第 1 章核对版本矩阵。

9.4 四大高频问题诊断 ​

① 白屏 ​

按顺序排查：

  1. devtools Console：大概率有 CSP 或 404 报错；
  2. Network/源码：资源路径是否正确？ Tauri 生产环境以自定义协议加载，资源引用要用相对路径（Vite 的 base: './'）， 写成 http://localhost:1420/... 在打包后必白；
  3. 用的是不是绝对磁盘路径（file:///）？生产环境不存在；
  4. 最小化验证：把根组件换成一行 Hello，确认不是业务 JS 早期抛错。

② 命令调用失败 ​

Console 信息特征原因处理
command X not found / invalid args命令未注册、名字拼错、参数名不符generate_handler! 中登记；Rust 参数名（snake_case）与前端传参一致
not allowed / not permittedcapability 未授权或窗口不在列表加权限；检查 windows 标签
命令返回 Err业务错误看 Rust 日志；前端 catch 并展示
参数反序列化失败类型不匹配（null/undefined 传给 String）TS 侧保证类型；Option<T> 才接受 null

③ 资源（图片/文件）不显示 ​

  • convertFileSrc 需要 asset 协议在 CSP img-src 中放行（第 7 章已配）；
  • 需要访问的目录受 scope 限制时，在 fs/asset 权限配置 scope；
  • Windows 路径反斜杠在 JS 字符串中需转义，优先让 Rust 返回路径。

④ 事件没收到 ​

  • 检查事件名常量是否完全一致（notes://changed）；
  • Rust 端确认引入了 use tauri::Emitter;（emit 是 trait 方法）；
  • 前端读取载荷用 event.payload（Tauri v1 曾是 data）；
  • 组件卸载时取消监听（listen 返回的 unlisten），避免重复订阅。

9.5 卡顿与性能问题 ​

最典型的坑：在同步命令里干重活，整个 UI 卡住。

rust
// 这样写会冻结窗口：命令在主线程执行
#[tauri::command]
fn crunch() { heavy_work(); }

诊断：卡顿期间 devtools 无响应、Rust 终端无输出 → 主线程被占。

解决（第 10 章展开）：

  • 重活改为异步 + spawn_blocking；
  • 进度通过事件 emit 给前端；
  • 前端频繁输入用防抖（本应用 500ms）。

找不到同名文件Linux大小写敏感：统一小写文件名

9.7 调试方法论（比答案更重要） ​

  1. 先分层：前端？Rust？打包器？——在对应层取证，别跨层瞎猜；
  2. 最小复现：删掉业务代码，直到问题消失，锁定最后删掉的那块；
  3. 证据先行：怀疑值不对就打印，怀疑顺序不对就加时间戳日志；
  4. 改一处：一次只动一个变量，否则无法建立因果；
  5. 条件编译分支：三平台日志都跑一遍，别让「我机器上没问题」成为最后结论。

9.8 FAQ ​

Q：console.log 在 tauri dev 终端看不到？ A：前端日志只在 WebView devtools 里。终端里的是 Rust 输出。

Q：release 包能开 devtools 吗？ A：临时加 devtools feature，用完去掉；不要带着它发布。

Q：panic 后只看到栈地址看不到源码行？ A：确认不是被 strip 的 release 档；debug 构建默认带符号。

Q：命令时好时坏？ A：检查是否有共享状态竞争（本应用用 Mutex）、异步竞态、重复事件订阅。

9.9 课后练习 ​

  1. 给应用接入 tauri-plugin-log，并在关于弹窗加「导出日志」。
  2. 故意制造一次白屏（错写资源路径），用本章流程在 5 分钟内定位。
  3. 把一个同步重活命令改成异步 + 进度事件，对比修复前后的窗口响应。
