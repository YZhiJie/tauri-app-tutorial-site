第 7 章 · 应用打包发布 ​

小塔：「一条命令走完前端构建 → Rust release 编译 → 平台安装器封装。但每一步背后都有要知道的细节。」

本章学习目标 ​

  • 讲清 tauri build 的完整流水线与三平台产物
  • 完成安装包元数据、图标、安装模式的配置
  • 理解并配置 CSP 内容安全策略
  • 掌握签名/公证概念与体积优化策略

7.1 一条命令的完整流水线 ​

bash
pnpm tauri build

执行顺序（对照 tauri.conf.json 的 build / bundle 段）：

text
1. beforeBuildCommand  → pnpm build（vue-tsc 类型检查 + vite 产出 dist/）
2. cargo build --release → Rust 编译 release 二进制（嵌入前端资源）
3. bundle → 调用各平台原生打包工具，产出安装器

关键点：前端资源被编译进 Rust 二进制（通过 frontendDist: ../dist）， 安装包内没有 Node.js 运行时，也没有整套 Chromium——这是 Tauri 体积优势的根源。

7.2 三平台产物与构建位置 ​

平台产物（位于 src-tauri/target/release/bundle/）只能在哪构建
Windowsnsis/*-setup.exe、msi/*.msiWindows
macOSmacos/*.app、dmg/*.dmgmacOS
Linuxdeb/*.deb、rpm/*.rpm、appimage/*.AppImageLinux

"targets": "all" 表示构建当前平台支持的全部格式；也可指定单一格式：

bash
pnpm tauri build --bundles nsis   # 只出 NSIS
pnpm tauri build --bundles dmg deb

两种 Windows 安装器怎么选 ​

  • NSIS（推荐默认）：自定义程度高、体积小、支持按用户安装（不要 UAC）；
  • MSI：企业环境友好，可通过组策略批量部署。

本应用配置了 NSIS 按用户安装：

json
"windows": { "nsis": { "installMode": "currentUser" } }

perMachine 需要管理员权限；both 让用户在安装时选择。

7.3 安装包元数据 ​

本章已在 bundle 中补全：

json
{
  "publisher": "AniNotes Tutorial",
  "copyright": "© 2025 AniNotes Tutorial",
  "category": "Productivity",
  "shortDescription": "动漫风格的轻量笔记应用",
  "longDescription": "……",
  "macOS": { "minimumSystemVersion": "10.15" }
}

这些不是摆设：

  • category：macOS App Store / Linux .desktop 的分类；
  • shortDescription：Linux 包管理器简介、Windows 安装器说明；
  • identifier（顶层）：全宇宙唯一的应用身份，更新、数据目录、签名都绑定它，发布后绝不能改。

附带额外资源 ​

如果应用需要随包附带配置文件、模型、静态数据：

json
"resources": ["resources/*.json", "resources/words.txt"]

代码中用 app.path().resource_dir() 定位。本应用暂无需求——不要预置想象中的资源。

7.4 图标：三种格式各司其职 ​

文件用途
icon.icoWindows 安装器/任务栏/可执行文件（内嵌多尺寸）
icon.icnsmacOS .app/.dmg/Finder（多分辨率含 Retina）
*.png 系列Linux 各桌面环境、安装器页面

生成方式（第 1 章已执行）：准备一张 1024×1024 无圆角 的源 PNG，然后：

bash
pnpm tauri icon ./app-icon.png

⚠️ 图标规范

  • 源图应为方形、无透明通道问题；macOS 圆角由系统裁剪，不要自己画圆角；
  • Windows 的 .ico 必须包含多尺寸（16~256），tauri icon 会自动处理；
  • 手改文件名后记得同步 bundle.icon 数组。

7.5 权限声明与 CSP ​

权限 = capability 文件 ​

我们用到的每个插件都在 default.json 中显式授权： dialog:default、notification:default……未声明的能力，即使代码里写了也会被拒绝。 这是默认安全（secure by default）模型，发布前最后检查一遍：权限集是否最小化。

CSP 内容安全策略 ​

本章把 csp: null（等于不设防）替换为：

text
default-src 'self';
img-src 'self' asset: http://asset.localhost;
style-src 'self' 'unsafe-inline';
script-src 'self'

逐条解释：

  • default-src 'self'：一切资源默认只能来自应用自身（打包进二进制的内容）；
  • script-src 'self'：禁止任何远程/内联脚本——这是防 XSS 的核心， 即使被注入了恶意脚本也无法执行；
  • style-src 'unsafe-inline'：样式放宽内联（框架的动态样式常见，风险低于脚本）；
  • img-src 允许 Tauri 的 asset 协议，未来用 convertFileSrc 显示本地图片时需要；
  • 没有任何远程域名白名单。真要加载远程 API/CDN，按「具体域名 + 具体指令」最小放开。

🦀 钳钳的悄悄话

开发模式下 Vite 需要 HMR（WebSocket、内联脚本），Tauri 会自动给 dev 放行； 所以「开发正常、打包后白屏/样式丢失」往往是 CSP 卡的，用浏览器 devtools 的 Console 看拦截报告。

7.6 macOS 签名与公证（概念） ​

未经签名的 .app：别人下载后打开会被 Gatekeeper 直接拦截。正式分发需要：

  1. 加入 Apple Developer Program（年费账号），取得：
    • Developer ID Application 证书（签名）；
  2. 本地构建时签名（CI 中通过环境变量传递证书与密码，绝不要提交到仓库）：
bash
pnpm tauri build
# Tauri 检测到签名环境变量后自动签名

相关环境变量：APPLE_CERTIFICATE、APPLE_CERTIFICATE_PASSWORD、 APP_SIGNING_IDENTITY、APPLE_ID、APPLE_PASSWORD、APPLE_TEAM_ID。

  1. 公证（Notarization）：签名后把包上传给 Apple 自动扫描，通过后装订票据， Gatekeeper 才会放行。Tauri 在 CI 中可自动完成（APPLE_* 变量齐全时）。

学习阶段：未配签名时产出的 .app/.dmg 可通过「右键 → 打开」本机测试， 这不是分发方案。第 8 章的更新机制同样要求签名（更新包需要可信来源）。

7.7 Linux 打包注意事项 ​

  • 运行时依赖 webkit2gtk-4.1（Ubuntu 22.04+ 官方源提供）； 构建机需要安装开发包（CI workflow 中给出 apt 列表）；
  • .deb 的依赖大部分由工具链自动探测，不要手写一堆版本号；
  • AppImage 自包含程度高、免安装，适合官网直接分发；
  • 各发行版包管理不同（deb/rpm），先覆盖主流 deb 系即可。

7.8 体积优化 ​

Rust release profile（本章已配置） ​

toml
[profile.release]
lto = "thin"       # 跨 crate 链接期优化
codegen-units = 1  # 更彻底的全量优化
opt-level = "s"    # 优先体积
strip = true       # 剥离符号
panic = "abort"    # 去除展开表

代价要清楚：编译变慢、catch_unwind 行为变化、崩溃现场缺少符号。 正式项目建议 strip 前另存一份带符号二进制用于崩溃分析。

前端侧 ​

  • Vite 生产构建自动 tree-shaking、压缩、按需分 chunk；
  • 大依赖（编辑器、图表）做路由级懒加载；
  • 图片用现代格式并压缩；本应用前端 gzip 后仅约 33 KB。

体积预期 ​

Tauri 应用安装包通常在 3~10 MB 量级（对比 Electron 常见 80 MB+）， 因为渲染层复用系统 WebView，不捆绑浏览器内核——代价就是第 6 章的引擎差异。

7.9 发布前检查清单 ​

  • [ ] 三个版本号一致（package.json / tauri.conf.json / Cargo.toml）
  • [ ] identifier 未变更；图标全格式齐全
  • [ ] capabilities 权限最小化；CSP 不包含远程域名通配
  • [ ] 全新机器（或新建用户）安装 → 首次启动 → 核心流程走通
  • [ ] 安装/卸载后数据目录行为符合预期
  • [ ] macOS 签名 + 公证状态确认；Windows SmartScreen 首次拦截已预期
  • [ ] 产物在三平台分别验证（不能用交叉编译互相替代）

现象原因解决

7.11 小结与课后练习 ​

本章你已完成：打包流水线、三平台产物、元数据/图标/安装模式、CSP 加固、签名公证概念、体积优化。

课后练习：

  1. 用 pnpm tauri build --bundles 分别只构建一种格式，对比产物内容。
  2. 给 CSP 增加一个真实场景：假设应用要显示某固定图床的远程图片，写出最小 img-src 放开方案并验证其他指令仍被拦截。
  3. 列出你所在目标平台「全新系统」需要补的全部运行依赖，整理成一页发布说明。
