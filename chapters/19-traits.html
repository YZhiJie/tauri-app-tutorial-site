第 19 章 · Trait 与泛型：可扩展的导出架构 ​

钳钳：「接口就像拼图底座——形状定好了，后面想插多少块新图案都行，底座本身不用动。」

本章学习目标 ​

  • 用 trait 把「行为契约」从「具体实现」中拆出来
  • 说清 impl Trait 与 dyn Trait 的取舍，以及 trait object 的对象安全规则
  • 用工厂函数做唯一的格式分发点，让命令层不依赖任何具体导出格式
  • 通过 #[serde(rename_all)] 把前端参数安全映射到 Rust 枚举
  • 为 trait 实现编写单元测试，验证多态行为而不依赖 Tauri

19.1 先看「不加抽象」的代价 ​

第 12 章的 export_all_notes 把格式硬编码在命令里：

rust
let body = format!("# {}\n\n{}\n", note.title, note.content);

需求来了：用户想导出 JSON。最直接的改法是加参数、加 if：

rust
let body = match format {
    "md" => format!("# {}\n\n{}\n", note.title, note.content),
    "json" => serde_json::to_string_pretty(note)?,
    _ => return Err(...),
};

再加 HTML、再加带 front-matter 的 Markdown……这个 match 会无限增长，而且每加一种格式，都要回到同一个函数里改。这就是「对扩展不开放」。

19.2 Trait：把「能做什么」写成契约 ​

[notes/export.rs](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/tauri-app-tutorial/app/src-tauri/src/notes/export.rs) 只定义一个契约：

rust
pub trait Exporter: Send + Sync {
    fn extension(&self) -> &'static str;
    fn render(&self, note: &Note) -> Result<String, AppError>;
}

每种格式独立实现：

rust
pub struct MarkdownExporter;

impl Exporter for MarkdownExporter {
    fn extension(&self) -> &'static str { "md" }
    fn render(&self, note: &Note) -> Result<String, AppError> {
        Ok(format!("# {}\n\n{}\n", note.title, note.content))
    }
}

命令层从此只说「给我一个 Exporter」：

rust
let exporter = exporter_for(format);
let ext = exporter.extension();
let body = exporter.render(&note)?;
let file_name = format!("{}.{}", safe_file_name(&note.title, &note.id), ext);

新增 PDF 导出时，命令层一行都不用改。

19.3 impl Trait 与 dyn Trait：静态分发 vs 动态分发 ​

写法分发方式编译产物适用场景
fn f(e: impl Exporter)单态化（静态）每个具体类型生成一份函数编译期已知类型、追求极致性能
fn f(e: &dyn Exporter)虚表（动态）一份函数 + vtable运行期选择、需要异构集合
Box<dyn Exporter>动态堆上对象 + vtable工厂返回、插件式扩展

我们的格式来自前端的字符串，只有运行期才知道，所以必须用 dyn：

rust
pub fn exporter_for(format: ExportFormat) -> Box<dyn Exporter> {
    match format {
        ExportFormat::Markdown => Box::new(MarkdownExporter),
        ExportFormat::Json => Box::new(JsonExporter),
    }
}

如果将来格式在编译期固定（比如「本产品只导 Markdown」），改成泛型参数 fn export<E: Exporter>(...) 可以省掉一次虚表跳转——但在文件 I/O 面前，这点开销可以忽略。

19.4 对象安全：为什么 trait 要加 Send + Sync ​

Box<dyn Trait> 要求 trait 是「对象安全」的：

  • 方法不能有泛型参数；
  • 不能返回 Self（除非 where Self: Sized）；
  • 不能有非 self 的关联函数。

extension 与 render 都满足。加上 Send + Sync 是因为第 21 章要把导出任务丢进 spawn_blocking：

rust
set.spawn_blocking(move || { ... });

虽然当前实现是在主任务里先 render 再移动字符串，但契约层面先声明线程安全，未来把 Arc<dyn Exporter> 共享给多个任务时不会突然编译失败。

19.5 前端参数如何变成 Rust 枚举 ​

Tauri 命令参数走 serde 反序列化，枚举加一个属性就能接受小写字符串：

rust
#[derive(Debug, Clone, Copy, Deserialize)]
#[serde(rename_all = "lowercase")]
pub enum ExportFormat {
    Markdown,
    Json,
}

前端调用（[src/lib/export.ts](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/tauri-app-tutorial/app/src/lib/export.ts)）：

ts
await invoke("export_all_notes", {
  dir,
  format: "markdown",
  onProgress: channel,
});

传错的字符串会在进入函数体之前就反序列化失败，错误信息是 serde 的标准提示，不需要手写 match 校验。

🦀 钳钳的悄悄话

参数用枚举而不是 String，等于把校验从「运行时 if」搬到了「反序列化入口」。能在边界挡住错误，就不要让它进入业务层。

19.6 JSON 导出为什么不用直接序列化 Note ​

rust
let payload = serde_json::json!({
    "id": note.id,
    "title": note.title,
    "content": note.content,
    "preview": note.summary(40),
    "updatedAt": note.updated_at,
    "version": note.version,
});
Ok(serde_json::to_string_pretty(&payload)?)

如果直接 serde_json::to_string_pretty(note)，内部模型一改名，导出文件格式就跟着变——而导出文件是对外契约。用 json! 现场构造，相当于给「内部模型」和「外部格式」之间加了一层防腐层。

19.7 测试：不依赖 Tauri 的多态验证 ​

export.rs 的测试直接构造 Note，分别调用两个实现：

rust
#[test]
fn markdown_has_title_and_body() {
    let out = MarkdownExporter.render(&sample()).unwrap();
    assert!(out.starts_with("# 测试\n\n"));
    assert!(out.ends_with("正文\n"));
}

#[test]
fn json_contains_preview() {
    let out = JsonExporter.render(&sample()).unwrap();
    let value: serde_json::Value = serde_json::from_str(&out).unwrap();
    assert_eq!(value["id"], "n-1");
    assert_eq!(value["version"], 3);
}

这就是 trait 带来的可测试性：渲染逻辑与 IPC、文件系统、窗口完全解耦，测试不需要启动 Tauri。

19.8 常见报错速查 ​

现象原因解决
the trait cannot be made into an objecttrait 含泛型方法或返回 Self改成对象安全签名，或给方法加 where Self: Sized
size for values of type ... cannot be known直接写了 dyn Exporter 而没有 Box / &用 Box<dyn Exporter> 或 &dyn Exporter
命令报 invalid args format前端传的字符串与 rename_all = "lowercase" 不匹配传 "markdown" / "json"，不要传 "MD"
新增格式后编译报「未覆盖所有分支」match 少了新枚举变体编译器会强制补全，这正是枚举优于字符串的地方
trait 对象跨线程报 not Sendtrait 没加 Send + Syncpub trait Exporter: Send + Sync
导出文件名出现乱码或空文件文件名规则重复实现且两处不一致统一调用 text::safe_file_name
