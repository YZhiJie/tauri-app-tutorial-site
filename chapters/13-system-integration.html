第 13 章 · 系统集成深入：托盘菜单与全局快捷键 ​

钳钳：「好用的桌面应用不吵不闹——平时缩在托盘里安静待着，主人一个快捷键就随叫随到。本章教你这两门『隐身术』。」

本章学习目标 ​

  • 理解系统托盘（Tray Icon）的定位：常驻入口而非第二个主界面
  • 用 TrayIconBuilder + 菜单 API 给 AniNotes 加上托盘菜单
  • 用 tauri-plugin-global-shortcut 注册全局快捷键，应用未聚焦也能唤起
  • 掌握「快捷键/托盘 → 同一套窗口显隐逻辑」的复用写法

13.1 为什么需要托盘和全局快捷键 ​

笔记类应用有个典型使用姿势：记录的冲动来得快去得也快。如果每次都要去 Dock / 任务栏找图标点一下，灵感可能已经跑了。两个系统集成能力解决这个问题：

能力解决什么交互
系统托盘应用「关窗不退进程」，常驻系统角落点击托盘图标弹菜单：显示窗口 / 退出
全局快捷键应用没有焦点时也能响应任何界面按 Cmd/Ctrl+Shift+Space 唤起/隐藏窗口

两者都落到同一个动作：切换主窗口显隐。所以本章的代码结构是：一个共用的 toggle_main_window 函数，托盘菜单和快捷键各挂一份。

🦀 钳钳的悄悄话

托盘不是「第二个主界面」。菜单项保持 2~4 个以内（显示窗口、退出是标配），复杂操作让用户打开主窗口再做。托盘菜单做成迷你应用是常见的过度设计。

13.2 系统托盘：菜单 + 事件 ​

托盘能力在 Tauri v2 里是内置但默认关闭的——需要先给 tauri crate 开 tray-icon feature（Cargo.toml）：

toml
# 第 13 章：托盘图标能力（tray-icon feature 默认关闭，需显式开启）
tauri = { version = "2", features = ["tray-icon"] }

然后在 setup 里组装托盘（main.rs）。三步：建菜单项 → 组装菜单 → 建托盘图标：

rust
use tauri::menu::{Menu, MenuItem};
use tauri::tray::TrayIconBuilder;

let show_item = MenuItem::with_id(app, "tray-show", "显示主窗口", true, None::<&str>)?;
let quit_item = MenuItem::with_id(app, "tray-quit", "退出 AniNotes", true, None::<&str>)?;
let tray_menu = Menu::with_items(app, &[&show_item, &quit_item])?;

TrayIconBuilder::new()
    // 直接复用窗口图标，教学项目不必单独设计托盘图标
    .icon(app.default_window_icon().expect("窗口图标已在 bundle 配置").clone())
    .menu(&tray_menu)
    // 单击图标也弹菜单（Windows 习惯；macOS 默认即如此）
    .show_menu_on_left_click(true)
    .on_menu_event(|app, event| match event.id.as_ref() {
        "tray-show" => toggle_main_window(app),
        "tray-quit" => app.exit(0),
        _ => {}
    })
    .build(app)?;

逐个点拆开看：

  1. MenuItem::with_id(app, id, 文案, 启用, 快捷键)：每个菜单项给一个字符串 id，点击事件里靠它区分谁被点了。最后一个参数是应用内加速键（如 Some("CmdOrControl+Q")），我们不需要，None::<&str> 让编译器推断类型。
  2. Menu::with_items(app, &[&show_item, &quit_item])：把菜单项按引用装进菜单。顺序即显示顺序。
  3. TrayIconBuilder：
    • .icon(...)：托盘图标。app.default_window_icon() 拿到 tauri.conf.json 里配置的窗口图标，教学项目直接复用。正式产品建议单独设计单色模板图标（macOS 菜单栏是黑白风格，彩色图标会突兀）。
    • .menu(&tray_menu)：挂菜单。
    • .show_menu_on_left_click(true)：左键单击也弹菜单。不设的话 Windows 上左键无响应（只有右键弹菜单），用户会以为图标坏了。
    • .on_menu_event(...)：菜单点击回调，event.id 就是建菜单项时给的 id。
    • .build(app)：真正创建。返回值是 TrayIcon，不想管理它的话丢弃即可——Tauri 会保活。

13.3 全局快捷键：未聚焦也能响应 ​

全局快捷键（global shortcut）与菜单加速键的区别：前者注册到操作系统，应用窗口没焦点、甚至最小化时都能收到；后者只在应用有焦点时生效。

这个能力由官方插件 tauri-plugin-global-shortcut 提供。三步：

第一步，Cargo.toml 加依赖：

toml
# 第 13 章：全局快捷键（应用未聚焦时也能响应）
tauri-plugin-global-shortcut = "2"

第二步，capabilities/default.json 授权（权限清单是 Tauri 的安全模型，不授权前端/系统会拒绝调用）：

json
"permissions": [
  "core:default",
  "dialog:default",
  "notification:default",
  "opener:default",
  "os:default",
  "process:default",
  "updater:default",
  "global-shortcut:default"
]

第三步，main.rs 注册插件并写处理器：

rust
use tauri_plugin_global_shortcut::ShortcutState;

.plugin(
    tauri_plugin_global_shortcut::Builder::new()
        .with_shortcut("CmdOrControl+Shift+Space")
        .expect("内置快捷键字符串必然合法")
        .with_handler(|app, _shortcut, event| {
            // 只在「按下」时响应，忽略松开，避免一次按键触发两次
            if event.state == ShortcutState::Pressed {
                toggle_main_window(app);
            }
        })
        .build(),
)

关键点：

  • 快捷键字符串语法：CmdOrControl+Shift+Space——修饰键在前、主键在最后，+ 连接。CmdOrControl 是跨平台写法：macOS 解析成 ⌘，Windows/Linux 解析成 Ctrl。
  • with_shortcut 返回 Result：字符串可能在运行时才解析失败。我们传的是编译期常量，用 expect 让「写错快捷键」在启动时立刻暴露，而不是静默吞掉。
  • event.state：一次按键产生两个事件——Pressed（按下）和 Released（松开）。只响应 Pressed，否则按一下窗口闪两次。
  • with_handler 的闭包能拿到 AppHandle，因此可以操作窗口——这正是「集成」的含义。

13.4 共用逻辑：toggle_main_window ​

托盘和快捷键都要「切换主窗口显隐」，抽成一个函数（main.rs 底部）：

rust
/// 显示/隐藏主窗口：托盘菜单与全局快捷键共用的逻辑
fn toggle_main_window(app: &tauri::AppHandle) {
    if let Some(window) = app.get_webview_window("main") {
        if window.is_visible().unwrap_or(false) {
            let _ = window.hide();
        } else {
            let _ = window.show();
            let _ = window.set_focus();
        }
    }
}

三个细节：

  1. get_webview_window("main")：按 label 找窗口，"main" 来自 tauri.conf.json 的 windows[0].label。多窗口应用这里可以换成别的 label。
  2. is_visible().unwrap_or(false)：可见性查询失败时保守地认为「不可见」，于是走显示分支——宁多显示一次，不错过用户的唤起请求。
  3. show() 之后必须 set_focus()：只 show 的话窗口可能出现在别的空间/虚拟桌面后面，不抢焦点等于没唤起。

13.5 跑起来看看 ​

bash
cd app
pnpm tauri dev

启动后注意三处变化：

  1. 菜单栏/通知区多出一个 AniNotes 图标，点击弹出「显示主窗口 / 退出 AniNotes」；
  2. 按 Cmd+Shift+Space（macOS）或 Ctrl+Shift+Space（Windows/Linux），窗口在显示/隐藏间切换；
  3. 选托盘菜单「退出 AniNotes」进程才真正结束——点窗口的关闭按钮只是关窗。

⚠️ macOS 小坑

macOS 上全局快捷键可能被系统或其他应用占用（比如 Cmd+Space 是 Spotlight）。with_shortcut 注册失败不会 panic，只是收不到事件——换个冷门组合（比如本章的 Cmd+Shift+Space）最省事。

13.7 小结与课后练习 ​

本章你已完成：托盘菜单（两个菜单项 + 事件分发）；全局快捷键注册与按下/松开事件区分；toggle_main_window 共用窗口显隐逻辑。应用升级到 v0.12.0，「常驻角落、随叫随到」的桌面应用体验齐了。

课后练习：

  1. 给托盘菜单加第三项「新建笔记」，点击后显示窗口并 emit 一个 tray://new-note 事件，前端监听后自动创建空白笔记。（练习托盘 → 前端的事件流）
  2. 把全局快捷键改成可配置：在设置面板里让用户输入快捷键串，前端调 globalShortcut.register(...)（@tauri-apps/plugin-global-shortcut 的 JS API）动态注册。体会「Builder 注册」与「运行时注册」的差别。
  3. macOS 上给托盘图标换单色模板图：准备一张 22×22 黑白 PNG，用 .icon() 换上，观察菜单栏效果。（练习图标资源管理）
