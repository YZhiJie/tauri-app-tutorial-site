第 5 章 · 系统 API 调用 ​

小塔：「系统对话框、通知、打开链接……Tauri 把这些都做成了官方插件，套路完全一致：装包 → 注册 → 授权。」

本章学习目标 ​

  • 掌握 Tauri 官方插件的统一使用模式（前端包 + Rust crate + capability 权限）
  • 学会五个系统插件：dialog / notification / opener / os / process
  • 完成「导入文件 → 落库 → 通知」和「导出笔记」两条完整业务链路

5.1 官方插件的统一套路 ​

本章的五个插件，安装方式完全一致，记住一次即可受用整个生态：

bash
# ① Rust crate（二选一）
cargo add tauri-plugin-dialog@2
# ② 前端包
pnpm add @tauri-apps/plugin-dialog
rust
// ③ main.rs 注册
.plugin(tauri_plugin_dialog::init())
json
// ④ capabilities/default.json 授权
"dialog:default"

🦀 钳钳的悄悄话

:default 是每个插件提供的「合理默认权限集」。需要更细控制时， 可以换成一个个具体权限（如 dialog:allow-open），还能在 capability 里写 scope。 第 7 章会把权限系统讲透。

5.2 dialog：原生对话框 ​

提供三类能力：打开文件 / 保存文件 / 消息框。原生外观，不是网页模拟。

ts
import { open, save, ask } from "@tauri-apps/plugin-dialog";

// 打开文件：返回路径字符串；多选时返回字符串数组；取消返回 null
const path = await open({
  multiple: false,
  filters: [{ name: "文本 / Markdown", extensions: ["txt", "md"] }],
});

// 保存文件：让用户选保存位置
const target = await save({
  defaultPath: "笔记.txt",
  filters: [{ name: "文本文件", extensions: ["txt"] }],
});

// 消息确认（Yes/No/Cancel），结果是布尔或 "yes"/"no"
const confirmed = await ask("确定删除这条笔记吗？", {
  title: "删除确认",
  kind: "warning",
});

要点：

  • filters 是必须重视的用户体验：写清扩展名，对话框会自动过滤；
  • open/save 只返回路径，不读写文件——拿到路径后怎么处理由你决定（本应用交给 Rust 命令读取，兼顾业务逻辑与安全）；
  • 消息框还有 message（提示）、confirm（确定/取消）两个 API。

5.3 notification：系统通知 ​

ts
import {
  isPermissionGranted,
  requestPermission,
  sendNotification,
} from "@tauri-apps/plugin-notification";

let granted = await isPermissionGranted();
if (!granted) {
  // 首次触发系统授权弹窗（macOS：用户可在系统设置中更改）
  granted = (await requestPermission()) === "granted";
}

if (granted) {
  sendNotification({
    title: "导入成功",
    body: "已导入「读书笔记」",
  });
}

平台行为差异：

平台表现
macOS首次弹系统授权框；通知出现在通知中心，遵守「专注模式」
Windows走 WinRT 通知，固定到操作中心
Linux走 freedesktop 通知规范（需要桌面环境支持）

⚠️ 不要滥用通知

通知是「打断用户」的能力。只在异步任务完成（导入/导出/更新）等用户预期的时刻使用， 每章都在强调：能力越大，默认行为越要克制。

5.4 opener：打开链接与路径 ​

ts
import { openUrl, openPath, revealItemInDir } from "@tauri-apps/plugin-opener";

await openUrl("https://tauri.app");            // 默认浏览器打开
await openPath(await appDataDir());            // 文件管理器打开目录
await revealItemInDir(`${dir}/notes/a.json`);  // 打开并选中某文件

为什么用 opener 而不是 shell 执行 start/open/xdg-open？

  • shell 插件允许执行任意命令，是重武器，需要严防命令注入；
  • opener 只做「用默认程序打开」这一件事，URL 走系统协议校验，攻击面小得多。
  • 能用 opener 就别碰 shell；只有真正需要执行外部程序时才用 shell（第 10 章演示安全用法）。

另外注意 https:// 链接：opener 会限制危险协议（如 file:// 由专门 API 处理）。

5.5 os：读取系统信息 ​

ts
import {
  platform, // 'windows' | 'macos' | 'linux'
  type,     // 更细的发行版类型
  version,  // 系统版本，可能为 null
  arch,     // 'x86_64' | 'aarch64' ...
  hostname, // async：主机名
} from "@tauri-apps/plugin-os";

注意两个坑（本章代码已处理）：

  • hostname() 是异步的（Promise<string | null>），其他几个是同步函数；
  • version() / hostname() 可能返回 null，用 ?? "unknown" 兜底。

5.6 process：进程控制 ​

ts
import { relaunch, exit } from "@tauri-apps/plugin-process";

await relaunch(); // 重启应用（第 8 章安装完更新后必用）
await exit(0);    // 退出；参数是退出码

「关于」弹窗里的重启/退出按钮就是它们。退出前记得确保该 flush 的数据已写完。

5.7 实战链路：导入与导出 ​

把上面的零件串成业务，就是本应用本章新增的两条链路：

导入 ​

text
dialog.open（用户选 txt/md）
      ↓ 路径
invoke import_note（Rust: 读取 UTF-8 -> 校验 -> 先持久化 -> 改内存）
      ↓ 返回新笔记
前端选中新笔记 + sendNotification（系统通知「导入成功」）
      ↓ Rust 同时 emit notes://changed
订阅者刷新列表

导出 ​

text
dialog.save（用户选保存位置）
      ↓ 路径
invoke export_note（Rust: 取笔记 -> 拼 Markdown -> fs::write）
      ↓
sendNotification（「导出成功」）

🦀 为什么文件读取也放 Rust

前端拿路径 → Rust 读取落库，这条链路让「编码校验、业务规则、持久化」 全部复用同一套经过冲突保护的代码。前端永远不该直接处理业务数据的原始字节。

5.8 常见报错速查 ​

现象原因解决
plugin not found 或 invoke 插件命令失败插件未在 Rust 注册Builder 中 .plugin(xxx::init())
调用插件返回 not allowedcapability 没授权加 xxx:default
通知不弹出权限被拒 / 专注模式 / Linux 无守护进程检查权限返回值；系统设置中恢复授权
open 拿到 null 后后续报错没处理用户取消判断返回值再继续
hostname 处类型报错它是 Promise，且可能为 nullawait + ?? 兜底
