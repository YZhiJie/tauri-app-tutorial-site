第 8 章 · 自动更新 ​

小塔：「更新能力 = 能远程改变用户机器上的代码。它必须建立在密码学信任链之上，而不是『那个 HTTPS 地址看起来没坏』。」

本章学习目标 ​

  • 理解 updater 的签名信任链与攻击面
  • 生成密钥、配置 endpoints 与更新清单 JSON
  • 实现「静默检查 → 用户确认 → 带进度下载 → 重启生效」完整流程
  • 用 GitHub Actions 完成三平台签名发布

8.1 更新的信任链（先理解再动手） ​

信任链是这个功能的地基，花三分钟读懂：

text
构建机（持有私钥）          用户机器（只内置公钥）
─────────────────          ─────────────────────
tauri build                  ① 请求清单 JSON，拿到新版本号、下载地址
  ↓ 对安装包签名               ② 下载安装包
产物 + .sig（签名）           ③ 用内置公钥验证签名
  ↓                          ④ 签名合法才安装；否则更新中止
清单 JSON 记录签名

关键推论：

  1. 私钥永远只存在于构建机/CI secrets 中，进了仓库等于游戏结束；
  2. 更新包即使被中间人替换、CDN 被攻破，签名不符就无法安装；
  3. 内置公钥写死在 tauri.conf.json，随旧版应用发布—— 密钥一旦丢失，你无法为已安装的老用户推送任何更新（所以要备份私钥）；
  4. 公钥可以公开，私钥口令建议设置。

8.2 生成签名密钥 ​

bash
pnpm tauri signer generate -w ~/.tauri/aninotes.key
  • 交互式：提示输入私钥口令（教学可用空口令，加 --ci -p ""）；
  • 产出两个文件：aninotes.key（私钥，保密）与 aninotes.key.pub（公钥）；
  • 公钥是一长串文本，复制到配置的 pubkey 字段（本章应用已完成）；
  • .gitignore 已加入 *.key 规则，双保险。

8.3 配置 updater ​

json
"plugins": {
  "updater": {
    "pubkey": "<aninotes.key.pub 的内容>",
    "endpoints": [
      "https://github.com/your-github-name/aninotes/releases/latest/download/{{target}}-{{arch}}.json"
    ]
  }
}
  • ：运行时替换为 windows / darwin / linux；
  • ：x86_64 / aarch64；
  • 还支持 （做灰度时可按版本返回不同内容）；
  • endpoints 可配多个（主备容灾）。

⚠️ 必做：替换占位符

本教程仓库未绑定 GitHub 用户名，地址中 your-github-name 必须换成你的真实仓库路径， 否则检查更新会 404。

8.4 更新清单 JSON 格式 ​

每个平台一个文件，如 darwin-aarch64.json：

json
{
  "version": "0.9.0",
  "notes": "修复若干问题；新增深色模式",
  "pub_date": "2025-09-26T00:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "<安装包对应 .sig 文件的全文>",
      "url": "https://github.com/you/aninotes/releases/download/v0.9.0/AniNotes_0.9.0_aarch64.app.tar.gz"
    }
  }
}

三平台「被更新的文件」各不相同，照抄前先判断：

平台更新包格式
WindowsNSIS -setup.exe 或 .msi
macOS.app.tar.gz（不是 .dmg！updater 自动产出）
Linux.AppImage（或 deb）

清单中的 version 必须高于客户端版本，updater 才会认为「有更新」。

8.5 前端完整流程 ​

本章应用代码（updater.ts）实现三级行为：

ts
// ① 只检查：返回 Update | null
const update = await check();

// ② 下载 + 安装，监听三类事件
await update.downloadAndInstall((event) => {
  // Started：event.data.contentLength 总大小（可能没有）
  // Progress：event.data.chunkLength 本次分片字节数（需累加）
  // Finished
});

// ③ 安装后重启生效
await relaunch();

两个产品级策略已落实：

  1. 启动时静默检查（silentCheckAndPrompt）：断网、404 一律不打扰用户； 只在确认有新版本时弹 ask 对话框，用户同意才下载——不偷跑流量；
  2. 关于弹窗手动检查：按钮显示进度（已下载 MB / 总 MB），失败有明确状态。

🦀 钳钳的悄悄话

check() 拉清单是轻量请求，可以每次启动做；但不要在应用内轮询。 下载必须用户知情——自动更新的「自动」指流程自动，不是替用户做决定。

8.6 GitHub Actions 发布工作流 ​

仓库已配置 .github/workflows/release.yml，发布一个新版本只需：

bash
# 1. 确认三处版本号一致并提交
# 2. 打 tag 推送
git tag v0.9.0
git push origin v0.9.0

工作流自动完成：

text
矩阵（win-x64 / macos-arm64 / macos-x64 / linux-x64）
  ↓ 装系统依赖（仅 Linux：webkit2gtk-4.1 等）
  ↓ pnpm install --no-frozen-lockfile
  ↓ tauri build（注入 TAURI_SIGNING_PRIVATE_KEY 后自动签名产出 .sig）
  ↓ 收集安装包，生成 {{target}}-{{arch}}.json
汇总 → softprops/action-gh-release 创建 Release（自动生成更新说明）

需要在仓库 Settings → Secrets and variables → Actions 添加：

Secret内容
TAURI_SIGNING_PRIVATE_KEYaninotes.key 文件全文
TAURI_SIGNING_PRIVATE_KEY_PASSWORD私钥口令（无口令可留空）

发布完成后验证：

  1. Release 页面包含四套安装包 + 四个 .json 清单；
  2. 打开 JSON，url 与 signature 都正确；
  3. 用上一版本应用执行「检查更新」走完全链路。

8.7 本地测试更新 ​

不用等 CI 也能验证信任链：

  1. 构建并安装 0.8.0（旧版）；
  2. 改版本号到 0.9.0，重新构建（本地会自动签名，需环境变量指向私钥）：
bash
export TAURI_SIGNING_PRIVATE_KEY="$(cat ~/.tauri/aninotes.key)"
pnpm tauri build
  1. 把安装包和 JSON 放到任意静态服务器（甚至本地 python3 -m http.server）， endpoints 指向它；
  2. 启动旧版 → 应检查到 0.9.0 → 下载 → 验签 → 重启。
  3. 篡改一下安装包再试：验签必须失败——这一步建议亲手做一次，直观感受保护存在。

8.8 灰度、回滚与注意事项 ​

  • 灰度发布：endpoints 中使用 ，服务端按版本决定是否放行； 或先让清单指向小范围渠道；
  • 回滚：不要把老版本重新「推」给新版客户端（版本号比较会忽略）； 正确做法是发布一个修复版本；更新包一旦发布不要覆盖（签名与 URL 都应不可变）；
  • 数据库迁移：新版若改了数据结构，更新后首次启动要能迁移旧数据， 并保留旧格式兼容（老用户可能直接跨多个版本更新）；
  • macOS：更新包同样需要来自签名的应用；CI 中建议配齐第 7 章的 Apple 证书。

8.9 常见报错速查 ​

现象原因解决
Signature verification failed包与签名不匹配 / 用错密钥用同一私钥重新构建签名；确认 pubkey 对应
检查更新无反应端点 404 / 占位符未替换 / 断网浏览器打开端点 URL 验证；静默策略会吞错，查日志
提示有更新但下载后没安装平台格式错误（如 macOS 用了 dmg）macOS 使用 .app.tar.gz
CI 签名步骤失败secret 未配置 / 口令不对检查两个 Secrets；本地空口令与 CI 保持一致
更新后版本号没变未 relaunch / 清单版本号写低安装后必须重启；version 严格高于旧版
Windows 更新触发 SmartScreen安装包未做代码签名积累信誉属预期，积累信誉或购买 Windows 代码签名证书
