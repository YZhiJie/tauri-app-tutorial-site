第 1 章 · 环境搭建与第一个窗口 ​

小塔：「在装软件之前，先花 5 分钟搞懂 Tauri 到底由什么组成，后面所有步骤都会变得理所当然。」

本章学习目标 ​

  • 理解 Tauri 的基本架构与它和 Electron 的区别
  • 在 Windows / macOS / Linux 上分别装好全部前置依赖
  • 用官方脚手架（或手动）创建第一个 Tauri 项目
  • 跑起 pnpm tauri dev，看到自己的第一个桌面窗口

1.1 Tauri 是什么 ​

Tauri 是一个用 Web 技术构建桌面（以及移动）应用的框架，但它和老牌方案 Electron 走了两条完全不同的路：

对比项ElectronTauri v2
渲染引擎打包 Chromium使用系统自带 WebView（Windows 是 WebView2、macOS 是 WKWebView、Linux 是 WebKitGTK）
后端语言Node.js（JS/TS）Rust
安装包体积通常 80 MB+通常 3~10 MB
内存占用较高显著更低
系统能力Node 生态直接可用通过 Rust 命令 + 官方插件按需授权
跨平台Win / macOS / LinuxWin / macOS / Linux（v2 还支持 iOS / Android）

一个 Tauri 应用运行时的结构非常简单：

┌──────────────────────────────────────────────┐
│              你的桌面应用进程                  │
│  ┌──────────────────┐   ┌──────────────────┐ │
│  │  前端（WebView）  │   │   Rust 核心       │ │
│  │  Vue / React ... │◄─►│  commands / 事件  │ │
│  │  HTML/CSS/JS     │   │  插件 / 系统 API  │ │
│  └──────────────────┘   └──────────────────┘ │
└──────────────────────────────────────────────┘
  • 前端跑在系统 WebView 里，就是你熟悉的网页；
  • Rust 核心负责所有真正的系统操作（读写文件、发通知、调系统命令……）；
  • 两侧通过两类通道交流：invoke（前端调用 Rust 命令，第 2 章）和 事件（双向消息广播，第 3 章）。

🦀 钳钳的悄悄话

正因为系统能力全部在 Rust 侧、前端必须「显式调用 + 显式授权」才能使用， Tauri 应用的默认安全面比「Node 直接全开」小得多。权限系统我们会在第 7 章深入。

1.2 前置依赖总览 ​

Tauri 需要三大件：Rust 工具链、系统 WebView 与编译工具链、Node.js（前端工具链）。

1.3 Windows 环境配置 ​

① Microsoft C++ Build Tools ​

Rust 在 Windows 上默认使用 MSVC 工具链，需要安装 Visual Studio C++ Build Tools。

安装时勾选 「使用 C++ 的桌面开发」 工作负载即可（它会包含 MSVC、Windows SDK 与链接器）。

② WebView2 Runtime ​

  • Windows 11 已内置；
  • Windows 10 较新版本也普遍预装；
  • 若没有，从微软官网安装 Evergreen Bootstrapper 即可。

③ Rust（rustup） ​

下载并运行 rustup-init.exe，一路默认回车，它会选择 stable-x86_64-pc-windows-msvc。

⚠️ 小塔提醒

安装完成后需要重新打开终端（让 PATH 环境变量生效），否则会提示「找不到 cargo」。

1.4 macOS 环境配置 ​

① Xcode Command Line Tools ​

提供 Clang 编译器与链接器：

bash
xcode-select --install

弹窗后按提示完成安装。WebView 使用系统自带的 WKWebView，无需额外安装任何东西。

② Rust（rustup） ​

bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

选择默认安装（1) Proceed with installation），完成后重新加载 shell：

bash
source "$HOME/.cargo/env"

国内网络较慢时可在安装前设置 rustup 与 crates.io 镜像（如中科大、字节 RsProxy），第 9 章给出具体配置。

1.5 Linux 环境配置 ​

Linux 是三者中「需要手动装的东西最多」的平台，核心是 WebKitGTK 及一堆 GTK 开发库。

Ubuntu / Debian（以 22.04+ 为例）：

bash
sudo apt update
sudo apt install -y \
  libwebkit2gtk-4.1-dev \
  build-essential \
  curl \
  wget \
  file \
  libxdo-dev \
  libssl-dev \
  libayatana-appindicator3-dev \
  librsvg2-dev

Fedora / CentOS Stream：

bash
sudo dnf group install "C Development Tools and Libraries"
sudo dnf install webkit2gtk4.1-devel openssl-devel curl wget file \
  libxdo-devel libappindicator-gtk3-devel librsvg2-devel

Arch Linux：

bash
sudo pacman -S --needed webkit2gtk-4.1 base-devel curl wget file \
  openssl libxdo libappindicator-gtk3 librsvg

⚠️ 注意 webkit2gtk-4.1

Tauri v2 依赖的是 WebKitGTK 4.1 API（旧教程里的 4.0 包名已过时）。 如果你的发行版较老、源里没有 4.1，请升级发行版或使用 Flatpak/容器构建，不要硬改 Tauri 版本。

1.6 Node.js 与包管理器 ​

前端工程需要 Node.js 18 或更高版本。本系列使用 pnpm：

bash
# 已装 Node 的情况下
npm install -g pnpm

# 验证
node -v
pnpm -v

本教程编写环境：Node 24、pnpm 11。Tauri CLI 以项目内依赖的方式安装（见 1.8）， 不要求全局安装，方便团队锁定同一 CLI 版本。

1.7 验证安装 ​

三个平台统一用以下命令自检，全部能输出版本号即环境就绪：

bash
rustc --version    # 例如 rustc 1.9x.x
cargo --version    # cargo 1.9x.x
node --version     # v18+ / v24
pnpm --version

1.8 创建第一个 Tauri 项目 ​

方式 A：官方脚手架（推荐新手） ​

bash
pnpm create tauri-app

按交互提示选择（本系列的选择用 粗体 标注）：

提示选择
Project nameaninotes
Identifiercom.aninotes.app（反向域名格式，打包时作为应用唯一标识）
Frontend languageTypeScript / TypeScript
UI templateVue
UI flavorTypeScript
Package managerpnpm

方式 B：直接使用本教程仓库 ​

本仓库的 app/ 目录就是逐章演进的同一项目，第 1 章对应的最小骨架已包含：

text
app/
├── package.json            # 前端依赖与脚本（含 @tauri-apps/cli）
├── vite.config.ts          # 固定 1420 端口
├── tsconfig.json
├── index.html
├── app-icon.png            # 图标源文件（动漫风格）
├── src/
│   ├── main.ts             # Vue 入口
│   ├── App.vue             # 欢迎卡片界面
│   └── styles.css          # 糖果色全局样式
└── src-tauri/
    ├── Cargo.toml          # Rust 依赖（tauri 2）
    ├── build.rs
    ├── tauri.conf.json     # Tauri 核心配置：窗口、构建、打包
    ├── capabilities/
    │   └── default.json    # 权限声明（当前只有 core:default）
    ├── icons/              # 由 tauri icon 生成的全平台图标
    └── src/
        └── main.rs         # Rust 入口

安装依赖并启动：

bash
cd app
pnpm install
pnpm tauri dev

1.9 核心配置文件速览 ​

src-tauri/tauri.conf.json 是整个应用的「总开关」，第 1 章版本只含最必要的字段：

json
{
  "$schema": "https://schema.tauri.app/config/2",
  "productName": "AniNotes",
  "version": "0.1.0",
  "identifier": "com.aninotes.app",
  "build": {
    "beforeDevCommand": "pnpm dev",
    "devUrl": "http://localhost:1420",
    "beforeBuildCommand": "pnpm build",
    "frontendDist": "../dist"
  },
  "app": {
    "windows": [
      { "label": "main", "title": "AniNotes 动漫笔记",
        "width": 960, "height": 640, "center": true }
    ],
    "security": { "csp": null }
  },
  "bundle": {
    "active": true,
    "targets": "all",
    "icon": ["icons/32x32.png", "icons/128x128.png",
      "icons/128x128@2x.png", "icons/icon.icns", "icons/icon.ico"]
  }
}
  • beforeDevCommand：启动 Tauri 前自动起前端 dev server；
  • devUrl：开发模式下窗口加载的地址；
  • frontendDist：打包模式加载的前端产物目录；
  • app.windows：声明式创建窗口，无需手写 Rust；
  • bundle：打包相关，第 7 章会大幅扩展它（但每次只对照 schema 加一小块）。

1.10 tauri dev 背后发生了什么 ​

第一次启动会比较慢（可能几分钟），因为要下载并编译所有 Rust 依赖。流程如下：

pnpm tauri dev
   │
   ├─ 1. 执行 beforeDevCommand：启动 Vite dev server (1420)
   ├─ 2. cargo 下载/编译 Rust 依赖（首次最慢，后续增量编译很快）
   ├─ 3. 编译你的 main.rs，并把 tauri.conf.json / capabilities 编入二进制
   └─ 4. 弹出原生窗口，加载 http://localhost:1420

🦀 钳钳的悄悄话

以后每章我们都是同一个节奏：改前端 → Rust 端加命令/插件 → tauri dev 验证。 Rust 依赖编译过一次后有缓存，第二次启动通常只要几秒。

1.11 常见问题速查 ​

❓ error: linker 'link.exe' not found（Windows） ​

MSVC Build Tools 没装或安装时没勾选「C++ 桌面开发」。重装该工作负载，然后重开终端。

❓ Linux：启动报 webkit 相关 .so 找不到 ​

WebKitGTK 开发包没装齐。对照 1.5 节执行对应发行版的安装命令，并确认装的是 4.1 包。

❓ 端口 1420 被占用 ​

Vite 配置了 strictPort，占用时会直接报错。关掉占用进程，或先单独 pnpm dev 排查。

❓ 窗口打开但白屏 ​

  • 确认 Vite dev server 是否已就绪（看终端有没有 ready in xxx ms）；
  • 在窗口里按快捷键打开 DevTools（开发模式：Windows/Linux F12，macOS Cmd+Option+I）看 Console；
  • 第 9 章有完整的白屏排查决策树。

❓ Rust 依赖下载太慢 ​

配置国内 crates.io 稀疏索引镜像（RsProxy / 中科大），配置方法见第 9 章。

1.12 小结与课后练习 ​

本章你已完成：理解 Tauri 架构 → 装好三平台依赖 → 创建项目 → 跑起第一个原生窗口。

课后练习：

  1. 把窗口默认尺寸改成 800 × 600，重新 tauri dev 观察变化（改的是哪个文件？）。
  2. 修改 App.vue 中的标题文案，保存后观察 热更新（HMR） 效果——窗口不重启就能看到变化。
  3. 思考题：为什么 Tauri 不需要像 Electron 那样把浏览器内核打进安装包？这会带来什么权衡？
