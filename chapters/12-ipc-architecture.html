第 12 章 · IPC 通信架构：invoke、Channel 与 Event ​

钳钳：「前端和后端之间有三条线路：一次性电话、专属回话管道、全域广播。用错线路，要么听不到进度，要么被无关消息淹没。本章教你选对线。」

本章学习目标 ​

  • 说清 invoke / Channel / Event 三种 IPC 方式的语义差异与选型标准
  • 用 tauri::ipc::Channel 实现「导出全部笔记」的实时进度推送
  • 用 serde 的 tag/content 枚举序列化构造前后端判别联合
  • 了解自定义协议（custom protocol）的概念与适用场景

12.1 三条通信线路：语义对比 ​

我们其实已经用过两条线路了，只是没有系统地比较过：

方式语义方向生命周期典型场景
invoke 命令请求-响应，一次问答前端 → Rust → 前端单次调用CRUD、查询（list_notes、word_count）
Channel调用专属的连续回话管道Rust → 前端（挂载在一次调用上）随命令调用创建，调用结束销毁进度汇报、流式结果、大文件分块
Event 事件全域广播/订阅双向需手动 listen / unlisten状态变更通知（notes://changed）、系统钩子

选型口诀：

  1. 一个答案就够 → invoke（90% 的命令都是它）；
  2. 一次调用期间要陆续说话 → Channel（进度条是它的招牌场景）；
  3. 不知道谁在听 / 多个窗口都要听 → Event（前端任何组件都能订阅）。

为什么进度不该用 Event？Event 是全局广播：你得发明事件名（如 export://progress）、前端要 listen 还要记得 unlisten，两次并发导出还会互相串台。Channel 把「这次调用的回话」收束为一个参数——天然隔离，天然好懂。

🦀 钳钳的悄悄话

Channel 的本质是一个「序列化后传给 Rust 的前端回调函数 id」。Rust 每 send 一次，Tauri 就把消息序列化并调用一次前端回调。所以它没有魔法——只是把「在这次调用里反复回调」做成了头等公民。

12.2 定义进度协议：判别联合 ​

先约定「线上跑的消息长什么样」。Rust 端用枚举 + serde 的 tag/content 属性（commands.rs）：

rust
/// 批量导出的进度消息（第 12 章：Channel 演示）
///
/// `#[serde(tag = "status", content = "data")]` 让枚举序列化成判别联合，
/// 前端收到的是这种形状：
/// - `{ "status": "started",  "data": { "total": 3 } }`
/// - `{ "status": "progress", "data": { "done": 1, "title": "..." } }`
/// - `{ "status": "finished" }`
#[derive(Debug, Clone, serde::Serialize)]
#[serde(tag = "status", content = "data", rename_all = "camelCase")]
pub enum ExportProgress {
    Started { total: usize },
    Progress { done: usize, title: String },
    Finished,
}

三个 serde 属性的作用：

  • tag = "status"：枚举变体名写进 status 字段（started / progress / finished）；
  • content = "data"：变体的字段打包进 data 对象；
  • rename_all = "camelCase"：变体名转小驼峰（Started → started）。

前端 lib/export.ts 里写出形状完全一致的 TS 类型：

ts
/** 与 Rust 端 ExportProgress 一一对应的判别联合（serde tag/content 的形状） */
export type ExportProgress =
  | { status: "started"; data: { total: number } }
  | { status: "progress"; data: { done: number; title: string } }
  | { status: "finished" };

这样前端 if (p.status === "progress") 时，TS 能自动收窄出 p.data.done 的类型——serde 的 tag/content 就是 TypeScript 判别联合的 Rust 写法。

12.3 Rust 端：把 Channel 当作命令参数 ​

export_all_notes 命令的签名里直接收一个 Channel（commands.rs）：

rust
/// 把全部笔记导出到指定目录（每条一个 .md 文件），进度经 Channel 实时推送
#[tauri::command]
pub async fn export_all_notes(
    store: State<'_, NotesStore>,
    dir: String,
    on_progress: tauri::ipc::Channel<ExportProgress>,
) -> Result<(), AppError> {
    let notes = store.list();
    // tauri::Error 经 From 自动转为 AppError::Emit
    on_progress.send(ExportProgress::Started { total: notes.len() })?;

    for (i, note) in notes.iter().enumerate() {
        let body = format!("# {}\n\n{}\n", note.title, note.content);
        // 文件名白名单过滤（与 storage 同思路）：非法字符一律替换为下划线，
        // 防路径穿越，也避开 Windows 保留字符；空标题退化为用 id 命名
        let safe: String = note
            .title
            .chars()
            .map(|c| if c.is_alphanumeric() || c == '-' || c == '_' { c } else { '_' })
            .collect();
        let name = if safe.is_empty() { &note.id } else { &safe };
        std::fs::write(std::path::Path::new(&dir).join(format!("{name}.md")), body)
            .map_err(|e| AppError::disk("写入导出文件失败", e))?;

        on_progress.send(ExportProgress::Progress {
            done: i + 1,
            title: note.title.clone(),
        })?;
    }

    on_progress.send(ExportProgress::Finished)?;
    Ok(())
}

要点：

  1. on_progress: Channel<ExportProgress> 就是一个普通命令参数——Tauri 反序列化时自动把它接上线；
  2. send 返回 Result<(), tauri::Error>，第 11 章的 From<tauri::Error> 让我们直接 ?； send 失败的典型原因是前端已经放弃了这次调用（页面跳转等），此时中止任务正是合理行为；
  3. 命令仍是 async fn：导出一百条笔记也不会卡 UI。

别忘了在 main.rs 的 generate_handler! 注册 export_all_notes。

12.4 前端：创建管道，传给命令 ​

新建 lib/export.ts：

ts
import { Channel, invoke, isTauri } from "@tauri-apps/api/core";
import { open } from "@tauri-apps/plugin-dialog";

export async function exportAllNotes(
  onProgress: (p: ExportProgress) => void,
): Promise<boolean> {
  if (!isTauri()) return false;
  const dir = await open({ directory: true });
  if (typeof dir !== "string") return false; // 用户取消

  // 创建管道：把它当作参数传给命令，Rust 侧凭它回话
  const channel = new Channel<ExportProgress>();
  channel.onmessage = onProgress;
  await invoke("export_all_notes", { dir, onProgress: channel });
  return true;
}

三行关键代码：

  1. new Channel<ExportProgress>()：创建管道（内部注册了一个回调 id）；
  2. channel.onmessage = onProgress：挂上消息处理器（注意属性名全小写 onmessage）；
  3. 把 channel 本身作为参数 onProgress 传给 invoke——Tauri 序列化时会把它翻译成 Rust 侧的 Channel<ExportProgress>。

参数名对齐规则不变：JS 的 onProgress 对应 Rust 的 on_progress（自动 camelCase ↔ snake_case 转换）。

12.5 UI 接线：进度 toast ​

NoteSidebar.vue 工具区加一个 📦 按钮并上抛事件：

html
<button title="导出全部笔记（带进度）" @click="emit('export-all')">📦</button>

App.vue 消费进度，驱动一条进度 toast：

ts
const exportState = ref("");

async function onExportAll() {
  try {
    const ok = await exportAllNotes((p) => {
      if (p.status === "started") {
        exportState.value = `开始导出 ${p.data.total} 条笔记…`;
      } else if (p.status === "progress") {
        exportState.value = `已导出 ${p.data.done} 条：${p.data.title}`;
      } else {
        exportState.value = "✅ 全部导出完成";
      }
    });
    if (ok) setTimeout(() => (exportState.value = ""), 3000);
  } catch (err) {
    exportState.value = "";
    errorMessage.value = `批量导出失败：${String(err)}`;
  }
}

样式上给 .progress-toast 与错误 toast 错开一行（top: 52px），互不遮挡。跑一次应用，点 📦 选个目录，就能看到进度逐条滚动——没有全局事件名，没有 listen/unlisten 样板。

12.6 概念拓展：自定义协议（custom protocol） ​

三条线路之外还有第四种「通信」：注册自定义 URL scheme（如 aninotes://），让 WebView 像请求网络资源一样请求 Rust。

  • 前端写 <img src="aninotes://note-cover/123">，Rust 端 register_uri_scheme_protocol 收到请求并返回字节；
  • 它不是「调用-响应」编程模型，而是把数据伪装成资源，浏览器缓存、<img>/<video> 等标签天然可用；
  • 典型场景：大量本地图片/音视频喂给 WebView（比 base64 塞进 invoke 返回值高效得多）、流式媒体。

本章不写实现——理解「何时需要它」即可，练习里留了动手入口。

12.7 常见报错速查 ​

现象原因解决
missing field onProgress / 参数反序列化失败传给 invoke 的参数名与 Rust 参数名不匹配JS onProgress ↔ Rust on_progress，检查拼写
channel.onmessage is not a function 之类属性名写成 onMessage（大写 M）正确属性名是全小写 onmessage
进度一条都收不到，但命令成功忘记给 channel.onmessage 赋值就 invoke先挂处理器再发起调用
Finished 后还想发消息报 send 失败调用已结束，Channel 随之关闭协议设计：Finished 必须是最后一条
想两个窗口同时收进度，Channel 不够Channel 是一对一管道改用 Event 广播（并自行管理订阅）

12.8 小结与课后练习 ​

本章你已完成：invoke / Channel / Event 三方式选型框架；ExportProgress 判别联合协议；export_all_notes 命令 + lib/export.ts 封装 + 进度 toast 全链路，应用升级到 v0.11.0。

课后练习：

  1. 把进度 toast 升级成真正的进度条：用 started.total 作分母、progress.done 作分子，渲染 <progress> 或 div 宽度百分比。
  2. 给 export_all_notes 加「覆盖保护」：目标目录里已存在同名 .md 时，通过 Channel 发一个 skipped 变体，前端统计跳过数量。（练习扩展 serde 枚举协议）
  3. 动手试自定义协议：在 main.rs 用 register_uri_scheme_protocol("aninotes", ...) 返回一张内置图片字节，前端 <img src="aninotes://localhost/cover"> 显示它。体会「把数据伪装成资源」与 invoke 的差异。
