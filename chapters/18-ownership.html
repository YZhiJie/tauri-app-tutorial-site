第 18 章 · 所有权与类型建模：借用、Cow 与生命周期 ​

小塔：「借来的东西要还，自己买的东西才能随便改——Rust 的所有权，其实就是这么朴素的一条生活常识。」

本章学习目标 ​

  • 用「移动 / 借用 / 可变借用」三条规则解释常见编译错误
  • 区分 String、&str、Cow<'_, str> 的适用场景，知道何时该零拷贝
  • 能读懂并写出带生命周期参数的结构体/方法签名
  • 用 Note::summary 实践「返回借用还是返回新值」的取舍
  • 理解 newtype 这种「用类型表达业务约束」的建模方式

18.1 三条规则，一张图 ​

Rust 的所有权规则只有三条：

  1. 每个值有且只有一个所有者；
  2. 同一时刻，要么有多个不可变借用（&T），要么有一个可变借用（&mut T）；
  3. 所有者离开作用域，值被释放。
text
        String 值
        ┌──────────┐
 owner  │ "hello"  │
  s ───►└──────────┘
              ▲   ▲
        &s    │   │  &mut s（独占）
       只读借用 ┘   └─ 期间不能再有别的借用

对应到我们的代码：

rust
let raw = fs::read_to_string(&path)?;   // raw: String，所有者
let content = normalize_newlines(&raw); // 借用 raw，不改它
db.insert(title, content.into_owned()).await?; // 需要所有权时再克隆

18.2 String 还是 &str：先问「谁拥有这段文本」 ​

类型拥有数据可增长典型场景
String✅✅数据库字段、要返回给前端的值、需要拼接的文本
&str❌（借用）❌函数入参、只读解析、切片
Cow<'_, str>可能拥有也可能借用条件性「大多数情况不用改，少数情况才分配」

函数参数优先用 &str：

rust
// 好：调用方传 String / &String / 字面量都能自动 deref
pub fn count_words(input: &str) -> usize { ... }

返回值则要看调用方是否需要长期持有。Note::summary 就是一个典型的两难：

  • 短笔记：内容本来就在 &self.content 里，复制一份纯属浪费；
  • 长笔记：必须截断，截断结果是一段新字符串。

Cow 正好表达「可能借用、可能拥有」：

rust
use std::borrow::Cow;

impl Note {
    pub fn summary(&self, max_chars: usize) -> Cow<'_, str> {
        if self.content.chars().count() <= max_chars {
            return Cow::Borrowed(self.content.as_str()); // 零拷贝
        }
        let cut: String = self.content.chars().take(max_chars).collect();
        Cow::Owned(format!("{cut}…"))
    }
}

Cow<'_, str> 里的 '_ 是关键：返回值的生命周期与 &self 绑定。编译器由此知道——摘要不能活得比笔记更久。如果写成 fn summary(&self) -> &str，短笔记分支能编译，长笔记分支却拿不出一个长期存活的引用；Cow 让两个分支都能返回。

🦀 钳钳的悄悄话

Cow 读作「copy-on-write」，但在 Rust 里它更像「clone-only-when-needed」。判断标准很简单：这段数据在 90% 的调用里都不会被修改吗？ 是，就用 Cow；否，直接 String 更省心。

18.3 生命周期：不是「活多久」，而是「借用关系」 ​

生命周期标注不改变值的存活时间，它只描述「多个引用之间的关系」。三个常见位置：

函数签名 ​

rust
pub fn normalize_newlines(input: &str) -> Cow<'_, str>

省略规则（elision）把返回值里的 '_ 绑定到唯一的输入引用 input：输出的借用不能超过输入。

结构体字段 ​

rust
pub struct NoteView<'a> {
    pub title: &'a str,
    pub content: &'a str,
}

这表示 NoteView 实例不能比它借用的字符串活得更久。本项目没有引入这种「借用视图」，因为笔记要跨线程、跨 IPC 传递，Note 直接拥有 String 更简单——生命周期的复杂度应该由真实需求驱动，而不是炫技。

方法里的 &self ​

rust
impl Note {
    pub fn summary(&self, max_chars: usize) -> Cow<'_, str>
}

'_ 自动绑定到 &self 的生命周期。等价于：

rust
pub fn summary<'a>(&'a self, max_chars: usize) -> Cow<'a, str>

18.4 借用的三种典型冲突 ​

冲突一：边遍历边修改 ​

rust
// ❌ 编译失败：notes 被不可变借用期间不能可变借用
for note in &notes {
    notes.push(note.clone());
}

解决：先收集要改的内容，循环结束后再改；或用索引循环（for i in 0..notes.len()）。

冲突二：返回局部变量的引用 ​

rust
// ❌ `s` 在函数结束时被释放，引用悬空
fn bad() -> &str {
    let s = String::from("hi");
    &s
}

解决：返回 String（转移所有权），或用 Cow 的 Owned 分支。

冲突三：跨 .await 持有借用 ​

rust
// ⚠️ 能否编译取决于 Future 是否 Send
let note = &notes[0];
some_async_call().await;
println!("{}", note.title);

在 Tauri 命令里，State<'_, T> 守卫跨 .await 是允许的（State 是 Send + Sync 的智能指针）；但如果你借的是 MutexGuard，跨 .await 通常不满足 Send。第 20 章的缓存采用 RwLock 读写后立刻释放，正是为了避开这个坑。

18.5 类型建模：让非法状态无法表示 ​

Rust 社区有句话：「Make invalid states unrepresentable」。AniNotes 的 Note 目前用 String 存 id，任何字符串都能塞进去。如果业务上 id 必须满足 n-<hex> 格式，可以考虑 newtype：

rust
#[derive(Debug, Clone, serde::Serialize, serde::Deserialize)]
#[serde(transparent)] // 序列化后仍是普通字符串，前端无感
pub struct NoteId(String);

impl NoteId {
    pub fn parse(raw: &str) -> Result<Self, AppError> {
        if raw.starts_with("n-") && raw[2..].chars().all(|c| c.is_ascii_hexdigit()) {
            Ok(Self(raw.to_string()))
        } else {
            Err(AppError::NotFound(raw.to_string()))
        }
    }

    pub fn as_str(&self) -> &str { &self.0 }
}

收益：

  • 命令参数从 id: String 改成 id: NoteId，反序列化阶段就完成校验；
  • 函数签名自解释，不会把 title 误传成 id；
  • 前端仍然收到普通字符串（#[serde(transparent)]）。

代价：数据库绑定、FromRow 映射、前端调用点都要跟着改。第 24 章会把这类「值得做但改动大」的重构列为架构债务清单——知道它、评估它、按需执行，比盲目重构更专业。

18.6 实战对比：三种导出的所有权策略 ​

看 [notes/export.rs](file:///Users/yangzhijie/Desktop/practice_projects/claude-code-test/tauri-app-tutorial/app/src-tauri/src/notes/export.rs) 里 JSON 导出的一小段：

rust
let payload = serde_json::json!({
    "id": note.id,              // 需要拥有？json! 会克隆
    "title": note.title,
    "content": note.content,
    "preview": note.summary(40), // 短笔记借用，长笔记分配
    "updatedAt": note.updated_at,
    "version": note.version,
});
  • note.id 等字段被 json! 复制进 Value，因为 json! 需要拥有数据；
  • preview 用 Cow 延迟分配：只有真的超长时才创建新字符串。

如果导出的是 10 万条笔记，这个差别就是「多复制一份全文」和「只复制前 40 个字符」的差别。所有权设计不是学术问题，它直接决定内存曲线。

18.7 常见报错速查 ​

报错 / 现象原因解决
cannot borrow as mutable because it is also borrowed as immutable不可变借用未结束就发起可变借用缩短借用作用域，或先收集再修改
returns a value referencing data owned by the current function返回了局部变量的引用返回 String / Cow::Owned
borrowed value does not live long enough借用比所有者活得更久调整作用域，或让结构体拥有数据
Cow<str> 上调用 .replace 报错Cow 没有 &mut self 的字符串方法先 .to_mut() 或 .into_owned()
future is not Send跨 .await 持有非 Send 的守卫（如 MutexGuard）在 await 前 drop 守卫，或改用 State
String 与 &str 比较结果不符合预期== 会做内容比较，但类型不匹配时可能先编译失败用 .as_str() 统一类型
